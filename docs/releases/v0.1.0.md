# macos-trash-cli v0.1.0

`macos-trash-cli` v0.1.0 moves approved top-level files and directories to the macOS system Trash.
It never permanently deletes an item, empties Trash, overwrites data, or falls back to direct Trash
directory manipulation. The release command is `tc`; the compile-time-isolated safety acceptance
command is `tc-test`.

## What is included

- macOS 13+ universal executable with `arm64` and `x86_64` slices;
- deterministic confirmation, Protected Path enforcement, dry-run planning, ordered batches, and
  schema-version-1 JSON results;
- Finder receipts preserving the exact system-returned Trash destination, including name-conflict
  renames;
- identity-verified symbolic-link handling with an owned Foundation Trash Finalizer;
- Optional unsigned universal `zip` and `tar.gz` archives, each accompanied by a detached SHA-256
  checksum. Apple Developer ID signing and notarization are not required (ADR-0004); Gatekeeper may
  ask for an explicit approval when an unsigned binary is opened.

## Compatibility and limitations

Compatibility options `-r`, `-R`, `-d`, and `-x` are accepted with no effect. `-P` warns that secure
overwrite is not performed; `-W` is unsupported. `--strict-options` rejects every no-effect option.
Moving an item to Trash does not immediately free disk space. Finder controls recovery, and Put Back
is not guaranteed for every volume or failure, especially when Finder Automation is unavailable or a
volume uses different Trash semantics.

The primary Homebrew strategy is a source-build formula in the maintained tap. A prebuilt Homebrew
bottle is not promised for v0.1.0; the formula is published after the tagged source and release
checksum are available. Until the tap is available, build the tagged source with Swift Package
Manager. The optional GitHub archives are unsigned convenience artifacts; verify their checksums
before use.

## Safety

The release and integration workflows never pass `/`, a home directory, the working directory, or a
system directory to `tc`. Real filesystem acceptance uses only compile-time-isolated `tc-test` and
the current authorized Test Safety Context Run Directory. No automated step enumerates or permanently
cleans the user's Trash. JSON output may contain sensitive absolute paths and should be protected by
the caller.
