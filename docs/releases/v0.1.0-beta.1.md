# macos-trash-cli v0.1.0-beta.1

This is the first beta of `macos-trash-cli`, published through GitHub's prerelease channel for
testing before stable v0.1.0. The production command is `tc`; `tc --version` reports
`tc 0.1.0-beta.1`.

## Included behavior

- Move approved top-level files and directories to the macOS system Trash, retaining Finder's
  exact returned destination.
- Preview with `--dry-run`, use deterministic confirmation and Protected Path checks, process
  ordered batches, and emit schema-version-1 JSON results.
- Handle symbolic links without following their targets, with identity-verified Trash Finalizers.
- Run on macOS 13 or later with a universal executable containing `arm64` and `x86_64` slices.

## Installation

Build the tagged source using Swift 6 and Swift Package Manager, or download the unsigned
`macos-trash-cli-v0.1.0-beta.1-macos-universal.zip` or `.tar.gz` archive and verify its accompanying
`.sha256` file before installation. See the [README](../../README.md#installation-and-release)
for commands. Each archive contains `tc`, LICENSE, NOTICE, README, and VERSION.

The Homebrew tap tracks stable releases only and is not updated for this beta. Archives have no
Apple Developer ID signing or notarization and may require explicit Gatekeeper approval. The Git
release tag must have a GitHub-verified cryptographic signature.

## Compatibility and limitations

`tc` never permanently deletes an item, empties Trash, or overwrites data. Moving an item to Trash
does not immediately free disk space. Compatibility options `-r`, `-R`, `-d`, and `-x` have no effect;
`-P` warns that secure overwrite is not performed, and `-W` is unsupported. `--strict-options`
rejects no-effect options.

Real Trash Operations require Finder Automation permission. Finder controls recovery; Put Back
is not guaranteed for every volume or failure state. Existing local-volume acceptance does not
establish universal support for external, network, iCloud, or File Provider locations. JSON results
contain absolute paths and should be protected by the caller.

The release pipeline runs non-destructive CI gates and the guarded integration entrypoint before
publishing. Real filesystem acceptance remains confined to the compile-time-isolated `tc-test`
Test Safety Context; the release pipeline does not call the real Trash API.
